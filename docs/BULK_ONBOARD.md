# 批量開戶及前端用戶管理

系統的日常帳戶管理已集中在前端「👥 用戶管理」，領袖毋須直接編輯 Google Sheet。

> ⚠️ 本文件所有編號、姓名、電郵均為示範用假資料（例如 `1234560001` / `陳大文` / `chan@example.org`），
> 不含任何真實成員資料。真實名單只會在你自己的瀏覽器內解析，再寫入你旅團自己的 Google Sheet。

## 可在前端完成的操作

- 單一開立可登入帳戶
- **從 YMIS 自訂報表 PDF 批量開戶**（推薦；見 [`YMIS_EXPORT.md`](YMIS_EXPORT.md)）
- 上傳 CSV 或貼上 JSON 批量開戶
- 自動產生臨時密碼（預設 `1234`）及下載成功帳戶清單
- 編輯姓名、Email、支部／單位
- 設定角色、勾選權限及獎章範圍
- 重設臨時密碼
- 停用及重新啟用帳戶（進度紀錄保留）
- 查看最近 200 項管理操作紀錄
- 審批成員自行提交的開戶申請

> Google Sheet 仍是資料儲存後端；只有初次部署 `Code.gs`、執行 `initializeSheets()` 及重新部署 Web App 時才需要進入 Apps Script。日常行政均可在前端完成。

## 推薦批量開戶流程（YMIS PDF）

1. 以支部領袖或以上帳戶登入。
2. 開啟「👥 用戶管理」→「📥 批量開戶」。
3. 依 [`YMIS_EXPORT.md`](YMIS_EXPORT.md) 在 YMIS 匯出自訂報表（欄位次序：**童軍成員編號 → 中文姓名 → 電郵地址**）。
4. （如有）輸入 PDF 密碼，上載報表。PDF 只在瀏覽器內解密，**不會上傳伺服器**。
5. 在匯入預覽勾選／修改資料，設定預設支部、角色；空白密碼預設為 `1234`（首次登入會要求更改）。
6. 確認開戶。前端會每 100 筆分批寫入；後端每個請求上限為 200 筆，避免 Apps Script 超時。
7. 立即下載成功帳戶及臨時密碼 CSV，安全地逐一交給用戶。
8. 用戶首次登入時必須更改臨時密碼。

讀不到 PDF 時，可把報表文字複製貼上，或改用下方 CSV／JSON。

## 備用：CSV／JSON

1. 下載 CSV 範本（`data/members_template.csv`）。
2. 填妥後上傳，先檢查前端預覽及錯誤提示；亦可貼上 JSON 陣列。
3. 確認開戶，並下載臨時密碼清單。

進階：若要在 Google Sheets 直接寫入 Users 工作表，可用 [`assets/batch-onboard/Code.gs`](../assets/batch-onboard/Code.gs)（與前端批量開戶獨立，只作後備）。

## CSV 欄位

| 欄位 | 必填 | 說明 |
|---|---:|---|
| `ymis` | 視乎角色 | 團員／執委必填 10 位數字（作為登入帳號）；領袖角色（`branch_leader` / `group_leader`）可留空，系統將自動編配內部 `L0001` 編號，領袖使用電郵登入 |
| `name` | 是 | 姓名 |
| `email` | 領袖／執委必填 | 領袖用作登入帳號及密碼重設；一般成員可留空 |
| `branch` | 否 | 支部或單位名稱（例如旅團名稱） |
| `role` | 是 | `member`、`exec_committee`、`branch_leader`、`group_leader`、`admin`（全團只能有一位活躍團長） |
| `can_tick` | 否 | `true` / `false`；`member` 不會獲得直接勾選權限 |
| `password` | 否 | 至少 4 位；留空時前端預設使用 `1234`（首次登入會要求更改） |
| `note` | 否 | 只供匯入前參考，不寫入 Users 工作表 |

## JSON 格式

亦可在批量開戶視窗貼上陣列：

```json
[
  {
    "ymis": "1234560001",
    "name": "陳大文",
    "email": "chan@example.org",
    "branch": "深資童軍支部",
    "role": "member",
    "can_tick": false,
    "password": ""
  },
  {
    "ymis": "",
    "name": "李領袖",
    "email": "leader@example.org",
    "branch": "深資童軍支部",
    "role": "branch_leader",
    "can_tick": true,
    "password": ""
  }
]
```

## 權限規則

- **團長唯一限制**：全團同一時間只允許一位活躍團長（`group_leader`）。若全團已有活躍團長，無論單一新增、批量開戶或更改角色為團長，後端均會拒絕並顯示現任團長姓名。如需換任，必須先將現任團長轉為其他角色（如支部領袖）或停用。
- **領袖免 YMIS 登入**：領袖（`group_leader` / `branch_leader`）在申請、單一開戶及批量開戶時均毋須填寫 YMIS 編號，後端自動編配內部 `Lxxxx` 唯一識別碼，領袖一律以電郵登入（舊有已具 10 位 YMIS 的領袖帳戶同時支援 YMIS 或電郵登入）。
- **角色階級管理**：
  - 支部領袖可管理執委及團員（不可開立或升任 admin、group_leader、branch_leader）。
  - 團長可管理支部領袖、執委及團員。
  - 管理員可管理團長、支部領袖、執委及團員，亦可直接建立另一個管理員帳戶；同級管理員不可互相停用或改權限。
  - 用戶不可更改或停用自己的角色／帳戶。
  - 批量資料即使填入較高角色，後端仍會按登入者權限拒絕，不只依賴前端檢查。

## 安全注意

- 臨時密碼只在批量結果頁及下載檔案中顯示；請勿放進公開群組。
- 重設密碼會撤銷該用戶現有登入。
- 停用帳戶不會刪除進度資料，可日後重新啟用。
- CSV／YMIS 匯入前會檢查 YMIS、Email、角色、密碼長度、重複資料及管理權限。
- YMIS PDF 與密碼只在瀏覽器內處理，不會經 `/api/proxy` 上傳。
